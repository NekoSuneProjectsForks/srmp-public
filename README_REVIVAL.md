# SRMP Revival (2026)

This revival targets **Slime Rancher 1**, the game SRMP was originally built for. It is not a Slime Rancher 2 port.

## Goals

- Preserve the later EOS/networking and compatibility work already present in the repository.
- Remove brittle developer-machine assumptions from the build where possible.
- Replace manual mod copying with a safe one-click Windows installer for the SRML build.
- Track the historical build-1584 bug list against the current source instead of blindly reintroducing old fixes.
- Require two-client gameplay validation before claiming timing/replication bugs are solved.

## One-click installation

Release ZIPs generated by `scripts/Package-Release.ps1` contain `payload/SRMP.dll`. Users install SRML first, close the game, then double-click `Install SRMP.cmd`.

The installer finds common Steam libraries and Epic locations, supports a custom `-GamePath`, validates the Slime Rancher 1 install, requires `SRML/Mods`, refuses to modify files while the game is running, backs up an existing `SRML/Mods/SRMP.dll`, verifies SHA-256 before and after copying, and writes `SRML/Mods/SRMP.install.json` so uninstall can restore the previous build.

## Building a release

Build the project's **SRML** configuration, then package the real output:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Package-Release.ps1 `
  -SrmpDll "C:\path\to\built\SRMP.dll" `
  -Version "2026.09.13"
```

The packager creates a Windows ZIP plus a SHA-256 checksum. It deliberately refuses to fabricate or substitute an unrelated binary.

## Reliability changes in this branch

- Chat input no longer schedules a delayed reopen when Return is pressed to send.
- Empty/null remote chat entries are ignored and chat history is bounded.
- Chat rendering restores IMGUI color state and safely wraps very long unbroken text.
- Plort collector authority falls back to the host while region ownership is still initializing, rather than letting all peers collect or throwing on incomplete state.
- Only the authoritative collector sends `StartCollection` synchronization.
- Harmony finalizers guarantee `Globals.HandlePacket` is cleared even when a custom packet returns early or a packet handler throws, preventing synchronization suppression from becoming stuck for the rest of the session.

## Bug verification

See `BUG_STATUS.md` and `TESTING.md`. Static inspection can prove several logic defects, but DLC/rejoin, drone, Gordo, slime emotion/plort, gadget performance and upgrade replication still require two live game clients before they should be marked verified.
